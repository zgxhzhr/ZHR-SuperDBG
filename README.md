# 执火人的超级调试器（SuperDbg）

药水 / 物品 / 实体三合一编辑器，附带防移除、超大血量、跨包兼容等增强功能。面向 Minecraft Forge 1.20.1。

## 功能一览

| 模块 | 触发条件 | 能做什么 |
|------|---------|---------|
| 药水编辑器 | 创造模式 + 副手持可编辑药水 + 主手空 + **Shift + 右键** | 自由修改喷溅/滞留/普通药水的效果、等级（0–2147483647）、时长（-1 永久），并可额外添加任意药水效果 |
| 物品编辑器 | 创造模式 + 副手持物品 + 主手空 + **Shift + 鼠标中键** | 修改物品名称、附魔（0–2147483647）、不可破坏、8 项属性（0–2147483647）；金斧可开启「调试斧」状态 |
| 实体编辑器 | 创造模式 + 主手持**调试斧** + 右键实体/空气 | 编辑实体的全部属性、药水效果、L2Hostility 词条、当前血量、防移除开关、交易列表、掉落覆盖、女仆回礼池；目标为玩家时可改头顶渲染名 |

额外能力：

- **防移除**：给实体加保护后，`/kill`、其他模组的清除指令/物品均失效；秒杀级伤害、`genericKill`、虚空伤害与「尾杀」型异常高频伤害一律免疫。判断伤害是否异常有两条维度：**绝对量级**（单次伤害达到 100 万即视为海量伤害，直接免疫）与**相对量级**（超过最大生命 2 倍免疫，超过最大生命但不足 2 倍则限幅为最大生命 15%），外加**高频统计**（同一游戏刻命中 ≥6 次或累计伤害 ≥1.5 倍最大生命、1 秒内命中 ≥20 次或累计伤害 ≥20 倍最大生命即免疫）。绝对量级那条不随最大生命放大，因此用「超大血量」把血量设到约 21 亿后，数亿级的「尾杀」伤害仍会被拦下，不会被灌死；反之对正常血量的生物，判据与以往一致，依旧可被正常战斗磨死。守卫同时覆盖 `hurt` 与实际扣血层 `actuallyHurt`（含覆写该方法的玩家），第三方直接调用 `actuallyHurt` 绕过 `hurt` 的路径同样拦截。Jade 安装后会在信息框显示「防移除」字样。
- **超大血量**：放开原版血量上限压缩，可设置最大血量至 `Integer.MAX_VALUE - 1`（约 21 亿），并修复大血量下 Jade 不显示生物信息的问题。
- **跨包兼容**：通过运行期检测自动适配不同整合包，yuyu 系模组的接管逻辑仅在通天之路生效，其它包零干预。
- **药水等级扩展渲染**：原版只显示 0–9 级（罗马数字 I–X），本模组对 10 级以上的效果补画阿拉伯数字。
- **聊天文本样式扩展**：`/tellraw` 与 `/title` 的文本参数可以在引号正文后直接写样式/颜色标记，还能写成多段、段与段之间指定等待时间（见[使用方法 4](#4-tellraw--title-文本样式扩展)）。
- **命令链间隔执行**：一行里用 `\间隔N秒` 把多条不同命令串起来，按间隔依次执行；聊天栏、命令方块、控制台与 RCON 全指令链路通用（见[使用方法 5](#5-命令链按间隔执行多条命令)）。
- **命令方块多行输入**：命令方块的输入界面多出一个「多行编辑…」按钮，可以分行书写长命令，完成时自动拼成一条命令填回输入框（见[使用方法 6](#6-命令方块多行输入界面)）。

## 安装

将构建产物 `superdbg-forge-1.20.1-1.0.0.jar` 放入 `.minecraft/mods` 目录。

**可选依赖**（不安装也能用，装了功能更多）：

- [Jade](https://www.curseforge.com/minecraft/mc-mods/jade) — 信息框显示「防移除」状态
- [L2Hostility](https://www.curseforge.com/minecraft/mc-mods/l2-hostility) — 实体编辑器出现「词条」页签，可设置词条等级与难度

## 使用方法

### 1. 药水编辑器

1. 创造模式下，把要编辑的药水放在**副手**
2. **主手保持空**
3. 按住 **Shift**，对任意方块或物品**右键**
4. 打开面板后可修改每条效果的等级（0–2147483647）和时长（填 `-1` 为永久）
5. 点左下角「**添加效果**」打开效果选择器：按译名（如「力量」「夜视」）或注册 id 搜索，点选任意药水效果（含模组效果）即追加到药水末尾；新增效果默认为 1 级、10 秒，可在列表中继续调整。原有的效果全部保留，未被改动的项也不会被覆盖

### 2. 物品编辑器

1. 创造模式下，把要编辑的物品放在**副手**
2. **主手保持空**
3. 按住 **Shift**，按**鼠标中键**
4. 面板内可修改名称、附魔、不可破坏、属性等

**获取调试斧**（实体编辑器的钥匙）：

1. 副手放一把**金斧**
2. 按上述方式打开物品编辑器
3. 勾选「调试状态」并确认 → 金斧变为「调试斧」，写入 `SuperDbgDebug` 标记（改名前的旧 `TiaoshiDebug` 调试斧仍可识别）
4. 这把调试斧拿在**主手**即可触发实体编辑器

### 3. 实体编辑器

前提：主手持**调试斧**（见上一步）。

| 操作 | 效果 |
|------|------|
| 右键**生物/玩家** | 打开该实体的编辑面板 |
| 右键**空气**（准星落空） | 打开自己的编辑面板 |

打开他人面板需满足权限规则：**编辑自己**始终允许；**编辑普通玩家**需编辑者为 OP（权限等级 ≥2）；**编辑 OP**（权限等级 ≥2 的玩家）仅服务器所有者（权限等级 4）可以打开——OP 之间不能互相打开；**编辑非玩家生物**需创造模式。

面板页签（标题栏右侧下拉切换，条件不满足的页签不列出）：

- **属性**：该实体已注册的全部属性（含模组属性）基础值直接输入框；底部可改当前生命值
- **效果**：药水效果增删改，等级 0–2147483647，时长 -1 永久
- **词条**（需安装 L2Hostility 且目标有词条能力）：设置 L2Hostility 词条等级与难度等级
- **饰品**（需安装 Curios）：调整饰品槽位数量
- **羁绊**（目标为车万女仆类实体时）：调试好感度、羁绊解锁/等级、待发礼物与羁绊能力
- **交易**（目标为村民/流浪商人等 Merchant 类实体时）：查看、修改、删除、新增交易项；物品选择器可直接搜索附魔（如「锋利」）并选择带具体等级的附魔书（锋利 I–V），附魔 NBT 随交易完整保存
- **获取**（目标为玩家时）：按「每组个数 × 数量」向玩家发放自定义物品，支持选择带具体附魔与等级的附魔书等带 NBT 的物品（发放后 NBT 完整保留）
- **掉落**（目标为非玩家、非女仆生物时）：覆盖该实体或该类实体（EntityType）的战利品表掉落
- **赠礼**（目标为女仆且安装了 TMA 车万女仆羁绊附属时）：按女仆个体配置 TMA「随机礼物」羁绊能力的回赠礼物池

**掉落页说明**：

- **作用域**：「本实体」只影响当前这只（存于实体自身 NBT，随存档走）；「全类型」影响该类所有实体（存于存档 data 目录）。两者同时存在时**单实体优先**，不叠加
- **模式**：「替换」只掉落本配置（原版战利品表不生效，但装备掉落、经验、凋灵之星等特殊硬编码掉落不受影响）；「追加」在原版掉落之外额外掉落本配置
- **每条规则**：物品（物品选择器挑选，附魔书等物品的 NBT 随掉落完整保留）、数量范围（最少–最多，闭区间均匀随机，留空按最少）、概率（百分比，支持一位小数）、抢夺加成（每级抢夺追加的概率百分比，可正可负）
- 取消勾选「启用覆盖」并确认即删除该作用域的覆盖配置，恢复原版掉落
- 打开编辑器时默认作用域自动对齐到**当前生效中**的覆盖（本实体覆盖优先，否则落在全类型）；停在另一作用域时，底部棕色提示行会指明对面作用域已配置覆盖

**赠礼页说明（女仆 + TMA）**：

- 配置存于该女仆自身 NBT，**按个体生效**，不影响其他女仆，也不改动 TMA 的全局礼物池标签
- 每条礼物：物品（物品选择器挑选，支持带附魔的附魔书）、数量范围（最少–最多闭区间随机）、权重（1–1000，权重越大越容易抽中）
- 保存后即接管 TMA「随机礼物」能力的产出；清空全部行再保存则删除个体配置，回退到 TMA 默认礼物池
- TLM 本体无回礼行为，未安装 TMA 时女仆不显示此页（掉落页也不显示）

底部通用控件：

- **渲染名**（目标为玩家时，位于面板底部）：仅替换该玩家的头顶悬浮名牌，不改真实名字（Tab 列表/聊天/死亡消息不变）；留空即清除。数据由调试器本体存储并全服同步，不依赖其他模组
- **防移除** 复选框：开启后该实体进入**完全免疫**状态——不允许收到任何伤害（`hurt` 与 `actuallyHurt` 两层入口一律拦截，怪物索敌/受击表现照旧，但血量不动）、不允许任何来源降低血量、不允许死亡（`die` 一律取消）。判定不区分伤害类型、来源模组或调用栈：**只要血量下降就视为非法**，包括用方法句柄直写血量同步数据、自研伤害实现等绕过手段。铁律只有一条例外——**调试器自身的设置**（编辑器设置当前血量/最大生命钳制、强制移除补刀）走内部旁路放行，并被记为新的回滚基准。因此守卫实体无法被磨死，也不会卡在死亡界面：唯一能改变它血量的只有调试器。血量核对分三层：`setHealth` 写入口直接拦截非法降血、血量同步数据写入后即时拉回（兜住绕过 `setHealth` 的直写）、每游戏刻以「上一刻血量」为基准兜底回滚
- **移除实体** 复选框（受保护实体如女仆不可移除）：直接移除该实体
- **确认 / 取消**

**女仆特殊处理**：车万女仆（Touhou Little Maid）的血量框会置灰，提交时无论输入什么数字都固定回满到当前血量上限。

**物品选择器**：交易、获取、掉落、赠礼四个页面的物品选择统一走同一个选择器，返回完整物品堆（含 NBT）。除物品中文名与注册 id 外，输入附魔的中文名（如「海之眷顾」）、英文名（如 `luck_of_the_sea`、`sharpness`）都能搜索到附魔书；有搜索词时追加附魔书条目，附魔书按具体附魔与等级分别列出（如锋利 I–V），悬停可查看附魔详情。

### 4. tellraw / title 文本样式扩展

`/tellraw <目标> <message>` 的 `message` 参数与 `/title <目标> title|subtitle|actionbar <title>` 的 `title` 参数，都能在引号正文之后直接跟样式/颜色标记。命令输入框下方那条灰色提示会把这些标记名平铺出来，照着敲即可。

统一写成「引号正文 + 若干标记」：

| 写法 | 含义 |
|------|------|
| `"正文" 斜体 黄色` | 不带值的标记作用于整段正文 |
| `"正文" 红色="正文"` | 带 `="片段"` 的标记只作用于该段中首次出现的那几个字 |
| `\间隔3.2秒` | 下一段比上一段晚 3.2 秒显示（反斜杠可省略，秒数可为小数） |

每个引号串是一条**独立的消息**，按先后依次显示：

```
tellraw @a "<狗修金>雪狐，帮我把那个——" blue="雪狐，帮我把那个——" \间隔3.2秒 "<酒狐>......？" 紫色="......？" 斜体="......？"
```

第一行立刻显示（后半句蓝色），3.2 秒后显示第二行（后半句紫色斜体）。不写 `\间隔N秒` 时下一段立即显示。`/title` 没有「多条依次显示」的语义，只会显示第一段。

可用标记（中英文名均可，不区分大小写）：

- **样式**：斜体、粗体、下划线、删除线、混淆
- **颜色**：红色、黄色、蓝色、绿色、紫色、橙色、青色、白色、黑色、灰色，另有粉色、浅蓝、深蓝、深绿、深灰、金色等

写法有误时会给出明确报错，不会静默生效：未知标记名、`=` 后没跟引号片段、片段在正文中不存在、间隔标记后面没有下一段、秒数不是数字，都会提示对应的红色错误。

原版写法完全不受影响：纯 JSON 文本组件、单个引号串、裸词都照旧交给原版处理。

### 5. 命令链：按间隔执行多条命令

一行里可以用 `\间隔N秒` 把多条**不同**的命令串起来，照写的先后依次执行，每条相对上一条等待指定秒数：

```
/tellraw @a "第一条" \间隔3.2秒 /summon zombie \间隔1.2秒 /tellraw @a "第三条"
```

`/tellraw @a "第一条"` 立即执行，3.2 秒后执行 `/summon zombie`，再过 1.2 秒执行 `/tellraw @a "第三条"`。所有命令都在**同一个来源**下执行（聊天栏用发送者、命令方块用方块本身），权限、执行位置与执行者身份都和直接敲这条命令完全一致。

- **间隔写法**：`\间隔3.2秒`，反斜杠可省略，秒数可为小数（`间隔1.2秒`）；整数秒直接写（`\间隔2秒`）。
- **开头也能写间隔**：把 `\间隔N秒` 写在最前面，第一条命令也会先等待再执行，例如 `/\间隔10秒 /tellraw @a "开场"`（聊天栏里最前面那个 `/` 是命令前缀，服务端会先去掉，真正的命令串是 `\间隔10秒 /tellraw @a "开场"`）。开头间隔之后的每条命令仍相对上一条计时。
- **与 tellraw 多段消息串行**：命令链的各段是**依次等待**的——上一段若是 tellraw 多段消息，会等它最后一段也发出去之后，才开始计算下一段的间隔。所以 `tellraw @a "开场" \间隔2秒 "正文" \间隔0.1秒 /summon ...` 里的 summon 会等消息播完再等 0.1 秒，而**不是**与消息并行、在第 0.1 秒就抢先执行。这样消息段与命令就能排在同一条时间轴上。
- **全指令链路通用**：聊天栏、命令方块（含命令方块矿车）、控制台与 RCON 执行的命令都汇聚到同一条链路，语法一致。
- **输入框不再报红**：命令链是服务端在执行前才接管的语法，客户端命令树里并没有它，原版会把整串判成「未知或不完整的命令」，把输入框里的字整行染红、并在输入框下方画一行红字。聊天栏与命令方块（含矿车）这两个入口本模组都按同一套切分规则识别命令链，命中时输入框文字恢复默认色、下方那行红字也不再出现；这纯粹是本地提示的适配，不影响命令的实际执行。
- **裸命令名也能识别**：下一条命令不写 `/` 时按「是否为已注册的命令名」判断，例如 `say 开始 间隔1秒 say 结束`；正文里出现的「间隔N秒」若后面不是命令名，不会被误当作分隔符。
- **与 tellraw 多段消息不冲突**：引号串内部一律不拆分；`\间隔` 后面若跟的是引号正文（tellraw 的段间写法），仍交给 tellraw 自己的多段解析（见[使用方法 4](#4-tellraw--title-文本样式扩展)）。

延迟期间来源可能已失效（命令方块被破坏、执行实体卸载等），此时该段会被跳过并记一条警告日志，不影响服务端运行。

### 6. 命令方块多行输入界面

命令方块（含命令方块矿车）的编辑界面里，命令输入框下方多出一个「多行编辑…」按钮。点开后会打开一块大的多行编辑区：**每行写一段**，回车换行，写完点「完成」自动按顺序拼成一条命令填回输入框。

之所以做这个界面，是因为 tellraw 这类命令一长，单行输入框只能左右滚动，看不清也难改。有了多行界面，上面那条样式扩展命令就能按行写：

```
tellraw @a "<狗修金>雪狐，帮我把那个——"
blue="雪狐，帮我把那个——"
\间隔3.2秒
"<酒狐>......？"
紫色="......？"
斜体="......？"
```

打开界面时，如果原有命令已经是单行写好的，本模组会按「段」自动折行（命令名与目标留在首行、第一个正文并到首行，之后每个正文、每个带 `=` 的标记、每个间隔标记各占一行），省去手工断行的功夫。折行只改断行位置、不改内容，合并回去仍是同一条命令。

- 界面底部实时显示「合并预览」，所见即所得，不必等提交才发现空格串错了位置
- 「完成」把多行内容合并成单行命令；「取消」或按 ESC 原样保留打开前的命令，不留改动
- 合并规则：去掉每行首尾空白、丢弃空行、用单个空格连接，因此缩进随便写、空行随便留，都不影响结果；引号内的空格属于正文，原样保留
- 原版单行输入框与命令补全照旧可用，改短命令不必进多行界面
- **长度上限按原版放开**：命令方块输入框与多行编辑区都容许写到 32500 字符。有些模组会把界面上所有输入框的上限统一压到几百字符（例如 512），长命令一贴进去就被截断；本模组在打开命令方块界面时按原版上限把输入长度恢复回来，多行编辑区也按自身上限截断，不受这类统一压制影响。该处理只作用于命令方块界面，不改动聊天栏等其它界面。

## 兼容性

已在以下整合包验证：

- **通天之路**（含 yuyu_core / yuyu_weapon / yuyu_compat）
- **主端 1.20.1**（无 yuyu）
- **元素觉醒 1.4.6**（无 yuyu，含 Sinytra Connector / FancyMenu / ModernUI / neruina 等 280 个模组）

关键技术处理：

- 热点方法一律用 `@Inject` 而非 `@Overwrite`，避免与 Sinytra Connector（fabric-entity-events-v1）等注入冲突
- yuyu 相关接管（血量伪造、死亡守卫、血量上限钳制）经运行期检测开关，非 yuyu 环境零干预
- 属性写入防 NaN，所有属性/血量最终钳制在 `Integer.MAX_VALUE - 1` 以内防溢出
- GUI `init()` 异常兜底，避免 FancyMenu / neruina 静默吞异常导致控件消失
